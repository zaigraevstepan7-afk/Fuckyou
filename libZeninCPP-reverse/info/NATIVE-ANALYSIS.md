# Разбор `libZeninCPP.so` по декомпиляции Ghidra

Результаты декомпиляции arm64-версии: **2273 функции** найдено, **2173 успешно
декомпилированы** в C (см. `../ghidra-decompiled/all_functions.c`, 26 МБ).
Дополнительно: `symbols.txt` (символы), `defined_strings.txt` (строки),
`functions_index.txt` (адрес → функция).

## Архитектура защиты (Dex2C / VMP «ZeninCPP»)

Подтверждено, что это коммерческий протектор **Dex2C** (бренд `ZeninCPP`).
Java-байткод ключевых классов перекомпилирован в нативный код этой `.so`.

### Точка входа `JNI_OnLoad` (`0x1376ec`)
```c
undefined8 JNI_OnLoad(long *param_1) {
  ...
  (**(code **)(*param_1 + 0x30))(param_1,&local_30,0x10006); // JavaVM->GetEnv, JNI 1.6
  FUN_00137084(local_30);                                     // инициализация рантайма
  return 0x10006;
}
```

### Инициализация рантайма `FUN_00137084` (`0x137084`)
- Вызывает виртуальный метод объекта-рантайма (`[*param_1 + 0x720]`);
- Заполняет большую глобальную **таблицу указателей** `DAT_006c45xx`
  значениями `PTR_FUN_006ad3xx…` — это таблица обработчиков нативных методов и
  подпрограмм дешифровки (диспетчер Dex2C).

### Динамическая регистрация нативов
- В коде **231 косвенный вызов `RegisterNatives`** (смещение `+0x6b8` в таблице
  функций `JNIEnv` на arm64). То есть библиотека регистрирует сотни нативных
  методов в рантайме, без символов `Java_*` — соответствие «натив ↔ Java-метод»
  скрыто намеренно.
- Java-стороны защиты: классы `ZeninCPP0/ZLoader` и `ZeninCPP0/hidden/Hidden0`
  (видны в строках) — именно их `registerNativesForClass(...)` и
  `special_clinit_*` вызываются из статических блоков `MainActivity`/`ConfigsActivity`.

## Подтверждённые возможности (по строкам и импортам в нативе)
- **Крипто:** `javax.crypto.spec.SecretKeySpec` → симметричное шифрование (AES)
  для строк/трафика; ключи генерируются/расшифровываются в рантайме.
- **Сеть:** `HttpURLConnection`, `HttpsURLConnection`, `X509TrustManager`/
  `TrustManager` → онлайн-проверка лицензионного ключа `ZE-********` поверх
  HTTPS с собственным/ослабленным доверием сертификату.
- **Ввод/UI-хуки:** `dispatchKeyEvent`, `onKeyDown`, `PasswordTransformationMethod`
  (поле ключа), `ComponentName` (запуск/поиск целевого приложения).
- **Идентификация бинаря:** `libZeninCPP.so`, сборка — Android NDK clang 11.0.5.

## Что осталось зашифрованным
Строковые литералы (адрес сервера авторизации, формат запроса, целевой пакет
игры, ключи) **не хранятся в открытом виде** — они расшифровываются нативными
подпрограммами из таблицы `DAT_006c45xx` на лету. В `defined_strings.txt` видны
только имена классов/методов для JNI-поиска.

### Чтобы достать секреты — динамика (Frida)
1. Хук таблицы `JNIEnv->RegisterNatives` → получить карту «натив ↔ Java-метод».
2. Хук подпрограмм-дешифраторов (функции из таблицы `DAT_006c45xx`) → дамп строк
   после расшифровки.
3. Хук `HttpURLConnection`/`SSLSocketFactory` → перехват реального запроса
   авторизации (URL, тело, заголовки) и проверка валидации ключа `ZE-*`.
