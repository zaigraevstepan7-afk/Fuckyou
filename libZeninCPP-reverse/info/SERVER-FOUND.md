# Сервер найден — interhack.shop

Адрес сервера, который статически был **зашифрован** в нативной либе, удалось
получить **перехватом сетевого трафика** (PCAPdroid), обойдя анти-Frida защиту
приложения — мы не трогали процесс, поэтому защита ничего не заметила.

## Что поймано (PCAPdroid, 30.06.2026 15:34)

| Параметр | Значение |
|---|---|
| Приложение | **Zenin External** (UID 10714) |
| DNS-запрос (UDP/53) | **`interhack.shop`** |
| TLS SNI (HTTPS/443) | **`interhack.shop`** |
| IP назначения | **`84.32.84.56:443`** |
| Протокол | HTTPS (TLS) |

## Что на сервере
`https://interhack.shop/` — **веб-панель авторизации чита**:
- Форма «Авторизация»: поля «Логин или Email», «Пароль», кнопка «Войти».
- Регистрация: ссылка `reg.php` («Нет аккаунта? Зарегистрироваться»).
- Язык — русский.

Это бэкенд, проверяющий лицензионный ключ `ZE-********` и (после авторизации)
отдающий payload/конфиги чита в приложение.

## Как это соотносится с реверсом
- В `libZeninCPP.so` адрес `interhack.shop` хранится **зашифрованным** и
  собирается в рантайме — поэтому статически (grep по бинарю) его не было видно
  (единственный открытый URL в либе — строка сборки LLVM).
- Запрос идёт по HTTPS, поэтому тело (ключ, ответ с payload) шифруется TLS.
  Чтобы прочитать **содержимое** запроса, в PCAPdroid нужно включить
  **расшифровку TLS** (встроенный mitm + установка его CA-сертификата) и смотреть
  вкладку «Содержимое» — там будет путь API (напр. `/api/...`, `/check.php`) и тело.

## Метод (воспроизведение, без root и без обхода анти-Frida)
1. PCAPdroid → Target app = Zenin External → Start (локальный VPN).
2. Запустить Zenin, попытаться авторизоваться ключом `ZE-...`.
3. PCAPdroid → Connections: видны DNS `interhack.shop` и TLS на `84.32.84.56:443`.
4. (Опц.) Включить TLS-decryption в PCAPdroid → вкладка «Содержимое» → путь и тело API.
